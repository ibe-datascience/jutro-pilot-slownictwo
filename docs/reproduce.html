Reproduce

Requirements, configuration, versions and the raw record of this run

This page shows the files a person needs in order to repeat the run, as they are in the repository: REQUIREMENTS.md, requirements.txt, requirements-lock.txt and config/biologia_sp.yaml.

Requirements

What you need besides the code in this repository. The published run (probka50) was made on macOS 26.5 (Apple Silicon, 18 GB RAM) with Python 3.12.2; nothing has been tested on Linux or Windows.

4. Input data and credentials

Set these in the zrodlo section of config/biologia_sp.yaml; the committed file holds the paths of the machine that made the published run.

Setting What it must point to
zrodlo.zpe_dir A local dump of the ZPE platform with catalog.jsonl, subjects.json, materials/<id>.manifest.json, materials/<id>_<unit>.html and texts/<id>.txt. Read-only for the pipeline. The dump is not distributed with this repository.
zrodlo.env_file A .env file with ANTHROPIC_API_KEY=... (the environment variable of the same name also works).
zrodlo.podstawa_pdf Present in the configuration, but no step reads it at the moment.

API use is bounded by llm.limit_kosztu_usd in the configuration: a request batch is refused when the spend so far plus its estimated cost would pass the limit. The requests of the published sample run cost about 32 USD: 26 USD for labelling 5,344 candidates with two models and adjudicating their disagreements, 5 USD for generating and rating pseudowords, and the rest for the lemmatisation benchmark, direct term extraction and concept grouping. Which model does which task is set in the llm section of the configuration. With --bez-llm no API call is made: step 5 is skipped and the other steps use only answers already in the local cache.

5. Running

. .venv/bin/activate
python -m jutro run --config config/biologia_sp.yaml --probka 50      # sample: 50 target + 300 contrast materials
python -m jutro run --config config/biologia_sp.yaml                  # full corpus
python -m jutro run --config config/biologia_sp.yaml --probka 50 --kroki raport   # one step only

Steps whose result already exists in data/<name>/<run>/ are skipped; --od-nowa forces them to run again. In the sample run the local computation took about 6 minutes for steps 1–4 and 2 minutes for step 7. The rest of the time is waiting for the API: about 10 minutes for the direct requests of the lemmatisation benchmark in step 2, and between 1 and 10 minutes for each batch job (five in step 5, two in step 7). The run left about 50 MB in data/.

Batch identifiers are written to data/<name>/<run>/llm/*.oczekujace.json as soon as a batch is sent. If the run is interrupted while a batch is being processed, the next run collects the results of that batch instead of sending (and paying for) the requests again.

To rebuild only the site from the committed results in wyniki/ (no ZPE dump, models or API key needed):

. .venv/bin/activate
python -m jutro site --config config/biologia_sp.yaml --probka 50

This renders site/*.qmd with Quarto and replaces docs/, the folder GitHub Pages serves, with the result. Step 8 of a normal run does the same. The pages contain no hard-coded numbers; they read wyniki/<name>/<run>/ while rendering.

6. What is and is not repeatable

  • Sampling of materials, the benchmark sample, the gold-set worksheet and template choice use the seed ziarno from the configuration.
  • Language-model answers are not deterministic. They are cached under data/<name>/<run>/llm/, which is not published, so a fresh run asks the models again and labels can differ.
  • Wuggy stops searching after pseudoslowa.wuggy_czas_s seconds per template, so on a slower or busier machine it can return fewer candidates.
  • The versions of all libraries used by a run are saved in wyniki/<name>/<run>/przebieg.json.
