1. Wuggy (Python package) and the official Polish plugin

What exists

Licence MIT (wuggy-1.1.2.dist-info/LICENSE, “Copyright (c) 2020 Emmanuel Keuleers”; GitHub API reports MIT; https://github.com/WuggyCode/wuggy/blob/master/LICENSE). GitHub master (commit 25de4ac1a608913bcdd633f312f3ac7dd2fead4a, 2026-04-17) is at version 1.2.0 in setup.py and is not on PyPI; it adds orthographic_lithuanian and a GUI-related plugin path.

How plugins are downloaded and stored (read from wuggy/generators/wuggygenerator.py, 1.1.2)

  • WuggyGenerator.load(name) looks for <site-packages>/wuggy/plugins/language_data/<name>/; if the folder is missing it calls download_language_plugin(name), which asks for y/n on stdin unless called with auto_download=True.
  • The download fetches exactly two files with urllib.request.urlopen from https://raw.githubusercontent.com/WuggyCode/wuggy_language_plugin_data/master/<name>/<name>.py and .../<name>/<name>.txt and writes them into that language_data/<name>/ folder inside site-packages.
  • WuggyGenerator.remove_downloaded_language_plugins() deletes the whole language_data folder.
  • Problem on this machine: the venv’s Python has no CA bundle configured, so the built-in download fails with ssl.SSLCertVerificationError: certificate verify failed: unable to get local issuer certificate. It works when SSL_CERT_FILE points at certifi’s bundle (tested, see below). A failed download leaves an empty language_data/orthographic_polish/ folder behind, and because load() only checks that the folder exists, it must be deleted before retrying.

Plugin file format and API

A plugin is a folder with two files:

  1. <name>.py defining a subclass of wuggy.plugins.baselanguageplugin.BaseLanguagePlugin (official plugins must name the class OfficialLanguagePlugin). Required members: default_data, default_neighbor_lexicon, default_word_lexicon, default_lookup_lexicon (file names, resolved relative to the folder of the .py file) and transform(self, input_sequence, frequency=1). The Polish plugin implements transform as self.pre_transform(input_sequence, frequency=frequency, language=self) and supplies oncpattern, a regex with three groups (onset, nucleus, coda) applied to each syllable. Inherited from the base class: output modes plain, syllabic, segmental, pass; statistics lexicality, ned1, old20, overlap, overlap_ratio, plain_length, transition_frequencies.
  2. <name>.txt, UTF-8, one entry per line, three tab-separated columns: word <TAB> word-syl-la-bi-fied (hyphens between syllables) <TAB> frequency. The same file serves as bigram-chain training data, lookup lexicon (word to syllabification), word lexicon (lexicality check) and neighbour lexicon (OLD20, ned1). For the lexicons Wuggy reads the last column as a float and keeps entries with frequency >= 0. For the bigram chain, BigramChain.load in 1.1.2 sets frequency = 1 for every line, so each entry counts once (type counts); the frequency column does not weight the transition frequencies. The Wuggy documentation calls the third column “occurrence per million words”; in the Polish file the values are proportions that sum to 1.000000.

To use a custom or modified plugin: g.load("any_name", local_language_plugin=MyPlugin()). The data folder is the folder containing the class’s .py file. The official docs (documentation/baselanguageplugin/baselanguageplugin.md in the Wuggy repo) say to copy the official .py/.txt and replace from ...baselanguageplugin import BaseLanguagePlugin with from wuggy import BaseLanguagePlugin. wuggy_plugins/load_local_plugin.py here achieves the same without editing the official file.

The Polish plugin (wuggy_plugins/orthographic_polish/)

  • orthographic_polish.py (1,017 bytes): header comment “Subsyllabic Polish, by Paweł Mandera, pawel.mandera@ugent.be”. Nucleus pattern: ia|ie|io|iu|ą|ę|a|e|i|o|u|y.
  • orthographic_polish.txt (39,841,583 bytes): 834,141 entries, all lower-case, no duplicate words, every line has 3 columns. Frequencies range from 9.828e-09 to 0.0283 (nie) and sum to 1.000000.
  • Source corpus: NOT documented in the plugin, the plugin repository (no README) or the Wuggy docs, so it is NOT VERIFIED. Observations only: the author is the first author of SUBTLEX-PL (Mandera et al. 2015, doi:10.3758/s13428-014-0489-4); the lexicon has more types than the 449,300 reported for SUBTLEX-PL, and its frequency values are not integer multiples of the smallest value, so it is not a plain count list from one corpus. Ask the maintainers before citing a source.
  • Licence of the plugin data: none stated. The repository has no licence file (GitHub API license: null, /license endpoint returns 404) and the files carry no licence header. The MIT licence of the wuggy package is in a different repository and does not mention the language data. Flagged as unclear.
  • Quirk: ó is missing from the nucleus pattern. For 36,607 of 834,141 entries (4.4%) at least one syllable does not match the onset-nucleus-coda regex, and Wuggy then treats the whole syllable as an “onset” segment (e.g. po-ró-wnać becomes segments p|o||ró|||wn|a|ć). Templates containing ó therefore get a much narrower and odder candidate set (see porównać below).
  • The lexicon is large and contains rare forms; lexicality == "N" only means “not in this file”. Candidates should still be screened against a dictionary before use as LexTALE nonwords.

Reproducibility

Wuggy shuffles its start keys with Python’s global random module (wuggy/utilities/bigramchain.py). Without a seed, repeated runs gave different pseudowords for the same template; PYTHONHASHSEED=0 did not fix it. Calling random.seed(<int>) right before generate_classic gave identical output within a process and across two separate processes. generate_classic also stops at max_search_time_per_sequence (default 10 s), so a slower machine can return fewer candidates.

Algorithm (as implemented in generatePseudo.R)

All source words have the same length L. For trigrams: pick a random source word and keep its first 3 letters; then, for each following position, take the last 2 letters built so far, find all source words with those 2 letters at that same position, and draw the next letter in proportion to how often it follows there. Bigram variant: same with 1 letter of context. A candidate is kept if it is not a source word, not in the exclusion list, not a duplicate, and passes the constraints. For a named language the app uses, from the WorldLex table, source words with BlogFreqPm > 0.5 and the exclusion list of all entries of that length. Default algorithm: bigram up to length 5, trigram from 6. Constraint presets in the R app for Polish: at most 3 consecutive consonants and at most 2 identical consecutive letters (the live Django site reported no presets for Polish).
